# 3/4 수정 결과 — 3·4·5단계

> 제안 관문에서 작가가 반영할 수정을 고른 뒤 읽는다. 승인 문장 치환, 전후 대조, 게시 전 교정과 판정, 결과 관문 카드를 다룬다.
> 관문 출력 순서·작가용 표기·추천 요청 형식·가독성 규칙은 SKILL.md의 `관문 진행`을, 모드별 관문 수는 SKILL.md의 `모드`를 따른다. `{BASE}`는 이 스킬의 기준 경로다.

## 3. 승인 항목 반영

**승인 문장 치환이 기본이다.** 2/4 원고 블록 보기에서 수정 후 문단 전문을 이미 작가에게 보였고 작가가 그 블록을 승인했으므로, 데스크가 승인 문장을 글자 그대로 반영본에 치환한다. 2/4 미리 대조에 쓴 치환 목록에서 승인 항목만 남겨 `python3 {BASE}/scripts/check.py --apply 치환.json 원고.md 반영본.md`로 넣는다. 스크립트는 원문 문장이 원고에 정확히 한 번 나올 때만 치환하고, 하나라도 0회·2회 이상이거나 구간이 겹치면 파일을 쓰지 않는다. 그때는 위치를 다시 잡거나 겹친 쌍을 하나로 합친다. 치환 뒤 전후 대조가 이어서 나오므로 4단계 1번 대조를 겸한다. 편집자를 다시 부르면 승인 문장이 비슷한 다른 문장으로 바뀔 위험이 있다.

편집자 재호출은 아래 경우에만 한다: 저자 답변을 받아 새 문장을 써야 할 때, 작가가 승인하면서 문장 수정을 지시했을 때, 구조 변경(문단 순서·이동)이 승인됐을 때. 이때는 1단계 편집자에게 이어서 보낸다(SendMessage). 그 에이전트가 없으면 새로 띄우고 `roles/editor.md`의 `선택 반영 재호출` 절을 적용하라고 지시한다.

재호출 때 넘길 것: 잠근 원고, 승인 이슈 전문(요약 금지), 반영 금지 목록(보류·유지 번호와 사용자 사유 원문), 저자 확인 답변(있을 때만), 보존 문구, 반영본 저장 경로(원본과 다른 파일). 데스크는 승인 문장 치환 밖에서 원고 문장을 새로 쓰지 않는다. 4/4 확정 `역할 수행` 줄에 반영 방식(`승인 문장 치환` 또는 `편집자 재호출`)을 적는다.

- 구조 변경은 승인된 경우에만 제목·도입·문단 순서·마무리를 함께 조정한다. 칼럼·에세이를 매뉴얼로 바꾸지 않는다.
- 사용자가 지운 장면이나 거부한 프레임은 되살리지 않는다.
- 근거 없는 외부 사실·수치·인용은 넣지 않고 `확인 필요`로 분리한다.

**범위 잠금 모드**: 지정 구간 밖의 문자·문단은 글자 그대로 둔다. 지정 구간의 앞뒤 연결 문장 한 개까지만 조정할 수 있고, 조정했으면 위치를 밝힌다.

완료 기준: 승인 이슈마다 수정 위치가 추적되고, 비대상 영역이 보존되며, 제목·도입·마무리가 같은 중심 판단을 유지한다. 분량은 원문의 120% 이내다. 넘으면 먼저 확인받는다.

## 4. 전후 대조와 기준 점검

승인 수정 구간과 앞뒤 문단만 본다. 원고 전체를 다시 고치지 않는다.

1. 스크립트로 대조한다. 눈으로 확인하지 않는다.

```text
python3 {BASE}/scripts/check.py 원본.md 반영본.md            # 문단 단위
python3 {BASE}/scripts/check.py 원본.md 반영본.md --sentence # 범위 잠금
```

   `변경` 문단마다 이슈를 붙인다. 승인 이슈에 걸리지 않은 변경은 범위 밖 변경이다. 분량·금지어·상투어 전후 건수도 기록한다. `숫자 보존`에 빠짐·새로 생김이 나오면 각 값을 승인 이슈(예: 확인 대기 수치 삭제)와 짝짓는다. 짝이 없는 값은 사실 훼손이라 되돌린다. 스크립트를 실행할 수 없는 환경이면 같은 기준으로 손 대조하고 `대조: 수동`을 적는다.
2. 원고별 용어집 → `voice/01-voice` → `02-glossary` → `03-anti-traces` 순으로 수정 구간을 점검한다. 판정이 갈리면 `04-examples`를 따른다.
3. 다음은 AI 흔적처럼 보여도 지우지 않는다: 실제 불확실성·조건·한계, 최신 승인 문장, 확인된 인용, 과거 경험의 자연스러운 과거형, 장르상 의도된 반복, 독자 이해에 필요한 한글 설명과 영문 병기.
4. 이슈마다 판정한다.

```text
ED-01  해결          — (확인 근거 한 줄)
ED-02  부분 해결     — (남은 부분)
ED-03  부분 해결(Q2대기) — 연결된 저자 확인 미답
ED-04  보류          — 사용자 선택
ED-06  새 문제       — (위치) — 재편집 필요로만 기록, 지금 고치지 않음
```

새 문제에는 이어지는 ID를 바로 붙인다. 다음 라운드는 승인본을 기준본으로 잠그고 이 ID들을 첫 후보로 올린다.

5. 경계를 확인한다: 범위 밖 변경, 지운 표현, 판단 강도, 경험·수치·인용의 출처.

**표적 재확인 모드**는 지정 이슈만 이 판정을 한다. 해결된 문제를 다른 말로 다시 제기하지 않는다.

완료 기준: 승인 이슈의 상태가 모두 판정되고, 원문에 없는 사실·경험 0건, 범위 밖 변경 0건(승인한 연결부 제외).

## 5. 게시 전 교정과 판정

구조를 다시 바꾸지 않는다. 아래만 본다.

- 맞춤법·띄어쓰기·문장부호
- 종결어미 일관성
- 용어·영문 병기 (첫 등장 `한글(영문)`, 이후 짧은 표기)
- 고유명사·날짜·수치·링크·인용·표·코드의 일치
- 채널 표기 기호: 한글 바로 뒤에 붙는 `_기울임_`·`*기울임*`은 마크다운 렌더러에서 기호째 보일 수 있다. 3/4 복사용 원고는 평문으로 내므로 강조 기호를 지우고, 강조 위치를 채널 게시 메모에 적는다
- 처리한 High 이슈의 마지막 확인

반영본에 `check.py --stats`를 다시 돌려 종결체 혼용 후보와 영문 병기 후보를 교정 입력으로 쓴다. 맞춤법·띄어쓰기는 스크립트가 보지 않으므로 데스크가 문장마다 읽어 확인한다.

교정 수정은 데스크가 직접 한다. 범위는 표기·맞춤법·문장부호·영문 병기 같은 문자 단위로 한정하고, 고친 곳마다 교정표에 남긴다. 교정도 `--apply`로 `반영본.md` → `교정본.md`에 넣어, 교정 밖 변경이 없는지 대조로 확인한다. 문장 구조를 바꿔야 하면 교정이 아니라 새 이슈다.

```text
교정 | 위치 | 수정 전 → 수정 후 | 근거
C1 | 1문단 | 커넥터와 스킬의 → 커넥터(Connector)와 스킬(Skill)의 | 용어집 첫 등장 병기
```

사용자가 `유지`로 고른 구간은 교정 대상에서 뺀다. 그 구간에 금지어·종결어미 혼용이 남아 있어도 고치지 않고 `유지 구간 잔여: 위치 — 항목`으로만 보고한다.

판정은 셋 중 하나로 낸다.

| 판정 | 조건 |
|---|---|
| 게시 가능 | 승인 이슈 전부 해결, 필수 저자 확인 0건, 확인 필요 사실 0건 |
| 게시 보류 | 필수 저자 확인 또는 확인 필요 사실이 남음 |
| 재편집 필요 | High 새 문제가 생겼거나 중심 판단이 흔들림 |

저자 확인은 2단계에서 `필수`(원고에 남은 문장이 그 답에 달림 — 반영한 문장이 저자 경험을 말하거나, 확인 대기 수치가 남은 경우)와 `선택`(답하면 보강할 수 있지만 지금 원고는 성립함)으로 나눠 둔다. 판정은 필수만 센다.

- **분류는 2단계에서 확정한다.** 2/4에서 정한 필수·선택을 3/4에서 그대로 쓴다. 3/4에서 바꿔야 하면(예: 반영한 문장이 달라져 답 없이도 성립하게 됨) `물음 N: 필수 → 선택 — 이유` 한 줄을 판정 줄 아래에 적는다. 조용히 바꾸지 않는다.
- **A안이 답 없이 성립하면 선택이다.** 저자 답에 따라 A안·B안이 갈리더라도, A안이 가정형("~한다면")이거나 원고 사실을 새로 만들지 않아 답 없이도 문장이 성립하면 처음부터 `선택`으로 분류한다. A안이 저자의 실제 경험·도구·사실을 전제해야 성립할 때만 `필수`다.

**결과 관문 카드.** 머리 줄은 `[3/4 수정 결과] 반영 N · 교정 N · 다음은 제목·도입·결론`처럼 다음 관문을 밝힌다(범위 잠금 3관문은 `[3/3 수정 결과] … · 다음은 저장`). 머리 줄 아래 순서:

1. 판정 한 줄 — 게시 보류면 무엇을 답하면 게시 가능이 되는지 같은 줄에 적는다
2. 바뀐 문장 표(수정 / 위치 / 수정 전 / 수정 후 / 결과) — 그대로 둔 수정도 한 행
3. 점검 결과 한 줄 — `맞춤법 수정 0 · 문장부호 교정 4 · 종결 혼용 0 · 숫자 보존 일치 · 범위 밖 변경 0 · 분량 106%`. 걸린 항목이 있을 때만 그 항목을 표 아래 한 줄로 짚는다
4. 수정 원고 전문(복사용 코드 블록)
5. 채널 게시 메모 한 줄(있을 때만) — 예: 고스트 소제목 H2 지정, 마크다운 기호 처리
6. 남은 물음 한 줄
7. 다음 단계에서 하는 일(`결과 관문 → 제목·도입·결론` 기본값) → 추천 요청 → 다른 요청

저장 질문·접수 형식 안내·`문체 기준`·`실행 지표` 줄은 3/4에서 내지 않고 4/4 확정 출력으로 옮긴다. 작가가 `4/4 건너뛰고 끝내줘`라고 하면 그 응답에서 4/4 확정 출력의 6~9번만 낸다.

완료 기준: 원고·검토 결과·미해결 항목이 분리되고, 승인받지 않은 정본 덮어쓰기와 외부 게시가 0건이다. 결과 관문 카드를 내고 멈췄다.
