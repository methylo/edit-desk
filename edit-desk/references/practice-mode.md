# 가상 원고 연습 모드

> 가상 원고 연습 모드에 들어갈 때만 읽는다. 관문 진행·단계 규칙은 SKILL.md를 그대로 따른다.

실제 원고 없이 주제만 받아, 결함을 심은 가상 원고를 만들고 0~6단계를 그대로 돌린다. 수정 과정을 익히거나 강의에서 시연할 때 쓴다.

## P. 가상 원고 준비

받을 것 다섯 가지. 사용자가 말한 값은 다시 묻지 않고, 없는 값은 기본값으로 정한 뒤 한 줄로 밝힌다.

| 항목 | 기본값 |
|---|---|
| 주제 | 필수. 없으면 한 번만 묻는다 |
| 채널 | 페이스북 |
| 분량 | 700자 안팎 (블로그 1,000자, 칼럼 800자) |
| 결함 수준 | 중 (결함 5개) — 약 3개 / 강 7개 |
| 진행 모드 | 개선형 (일괄 개선·범위 잠금·진단만 중 지정 가능) |

```text
가상 원고: 주제 ○○ · 채널 페이스북 · 700자 · 결함 중(5개) · 진행 개선형
```

결함은 아래 목록에서 고르고, 주제에 맞는 것을 우선한다. 같은 유형을 두 번 넣지 않는다.

| 코드 | 결함 유형 | 예 |
|---|---|---|
| F1 | 일반론 도입 | "AI 시대가 급변하고 있습니다"로 시작 |
| F2 | 금지어·과장 | 매우, 획기적인, 완벽한 |
| F3 | 근거 없는 수치 | "시간이 70% 줄었다", "기업의 80%가" |
| F4 | 문단 사이 모순 | 앞에서 "파트너", 뒤에서 "도구일 뿐" |
| F5 | 종결어미 혼용 | ~다체 사이에 ~합니다체 문단 |
| F6 | 용어 혼용 | 같은 대상을 세 이름으로 부름 |
| F7 | 설명 없는 약어 | RAG, LLM을 풀지 않고 씀 |
| F8 | 원인 공백 | 사건은 있는데 원인이 원고에 없음 → 저자 확인 대상 |
| F9 | 일반화·행동 촉구 마무리 | "여러분도 ~해 보시기 바랍니다" |
| F10 | 같은 말 반복 | 제목·도입·결말이 같은 문장 |

작성 규칙:

- 결함이 아닌 부분은 자연스럽게 쓴다. 지킬 만한 장면 하나와 판단 문장 하나는 꼭 넣어, 보존 판단도 연습하게 한다.
- 원고 맨 위에 `[가상 원고]`를 붙인다. 1인칭 경험은 지어낸 것이다. 실존 인물·기관·제품 수치는 쓰지 않는다. 제품명은 일반 명사로 쓰거나 공개된 이름만 쓴다.
- 원고는 작업 폴더가 있으면 `가상원고_{주제}.md`로 저장하고, 없으면 대화에만 둔다. 반영본은 따로 저장한다(3단계 규칙).
- **결함 답안지**(코드·위치·심은 문장)는 데스크만 갖고 출력하지 않는다. 독자·편집자 서브에이전트에게도 넘기지 않는다. 답안을 알면 진단이 연습이 되지 않는다.

출력: 가상 원고 전문 → 준비 선언 한 줄 → 바로 0단계로 넘어간다. 0단계 중심 판단은 데스크가 정해 밝히고, 사용자가 다르게 정하면 그 값을 쓴다.

## 저자 확인 처리

가상 원고의 저자 확인 질문은 사용자가 지어서 답하거나 `가상으로 답해줘`라고 할 수 있다. 데스크가 지어서 답하면 답 앞에 `[가상 답]`을 붙인다. 답이 없으면 실제 원고와 똑같이 `게시 보류`로 판정한다.

## 마지막 단계: 결함 대조

4/4 확정 뒤에 답안지를 공개하고 대조표를 낸다.

```text
결함 대조 | 코드 | 위치 | 심은 문장 | 진단에서 | 처리
1 | F3 | 2문단 | 강의 준비 시간이 70% 줄었다 | ED-05로 잡음 | 저자 확인 Q2
2 | F5 | 4문단 | (합니다체 문단) | 잡음 | 해결
3 | F10 | 제목·7문단 | ... | 놓침 | —
탐지: 4/5 · 놓친 결함: F10 · 결함 외 지적: 2건
```

- `놓침`이 나오면 그 결함이 진단 일곱 축 중 어디서 잡혔어야 하는지 한 줄로 적는다.
- `결함 외 지적`은 답안지에 없지만 진단이 찾은 문제다. 과잉 지적인지 실제 문제인지 데스크가 한 줄로 판정한다.
