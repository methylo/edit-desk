# 1/4 원고 확인 — 접수 질문과 0단계

> 원고를 받으면 가장 먼저 읽는다. 접수 질문, 0단계(접수·잠금·기초 수치·범위 판정), 확인 관문 카드, 진단 선행 실행을 다룬다.
> 관문 출력 순서·작가용 표기·추천 요청 형식·가독성 규칙은 SKILL.md의 `관문 진행`을, 모드별 관문 수는 SKILL.md의 `모드`를 따른다. `{BASE}`는 이 스킬의 기준 경로다.

## 접수 질문 — 0단계 앞

원고를 받았는데 **원고 종류**(설명글·칼럼·에세이·책 챕터 등)나 **발행 채널**이 요청·파일 이름·대화 어디에도 없으면, 0단계를 시작하기 전에 질문 하나만 묻는다. 채널에 따라 문단 길이·소제목·마크다운 표기·마무리 기준이 달라지므로 추정으로 진행하지 않는다.

- AskUserQuestion이 있으면 그것으로, 없으면 평문으로 묻는다. 질문 하나, 선택지 3개 + 직접 입력.
- 원고 본문에서 채널 단서(블로그 소제목, 해시태그, 장 번호 등)가 보이면 그 채널을 첫 선택지에 `(추정)`으로 둔다.
- 이미 채널·종류가 정해져 있으면 묻지 않고 바로 0단계로 간다. 독자·지킬 문장은 없어도 묻지 않는다(확인 관문에서 묻는다).
- 질문 아래에 한 줄로 답한 뒤 하는 일을 적는다: `답을 주시면 원고를 기준본으로 잠그고 분량·문장 길이·금지어 같은 기초 수치를 낸 뒤, 채널·독자·중심 판단·지킬 문장을 확인받습니다.`
- 답을 받으면 모드 선언 줄을 낸 뒤 0단계를 시작한다.

```text
이 원고는 어디에 발행하는 어떤 글입니까?
1. 고스트 블로그 — 설명글·칼럼
2. sshong.com 워드프레스 — SEO 검색 유입 글
3. 페이스북 롱폼
직접 입력: 네이버·브런치·책 챕터 등. 예상 독자나 꼭 지킬 문장이 있으면 함께 적어 주십시오.
```

작가가 처음부터 아래 형식으로 원고를 주면 질문 없이 진행한다. 접수 질문을 낸 첫 원고의 마무리 관문 확정 출력 끝에 이 형식을 한 번 안내한다.

```text
원고 종류: 블로그 설명글
발행 채널: 고스트 블로그
예상 독자: (선택)
지킬 문장: (선택)
진행: 빠르게 / 정식으로 (선택)
```

## 0. 접수와 원본 잠금

**기준 경로 확보.** 이 스킬의 Base directory를 `BASE`로 기록하고 `{BASE}/roles/`, `{BASE}/voice/`의 **절대 경로**를 만든다. 서브에이전트는 상대 경로를 자기 작업 폴더 기준으로 읽으므로 반드시 절대 경로로 넘긴다. voice 파일이 하나라도 없으면 그 층은 최소 카드로 대신하고 출력 말미에 적는다.

아래 접수 카드를 내부에서 채운다. 대화나 파일에서 확인된 항목은 다시 묻지 않는다.

```text
원고 기준본:
편집 모드:
편집 범위:
글의 목적:
채널:
예상 독자:
중심 판단 한 문장:
제목·도입·결론 범위 판정:
반드시 보존할 경험·문장·표현:
수정 금지 영역:
사실 확인·출처 재검토 항목:
원고별 용어집 경로:
저장 요청과 경로:
```

원고가 파일이면 같은 폴더에서 `00 승인본.md`와 `*_용어집.md`를 먼저 찾는다. 승인본이 있으면 그것이 기준본이다.

**작업 폴더.** 스크립트와 서브에이전트는 파일을 읽으므로 기준본을 세션 임시 작업 폴더(작가가 연결한 폴더 밖)에 `원고.md`로 둔다.

- 원고가 파일·첨부면 복사한다(cp). 옮겨 적지 않는다. 옮겨 적으면 기준본이 작가 원문과 달라져도 알 수 없다.
- 대화 본문으로만 받았으면 그대로 옮겨 적은 뒤 문단 수와 문단마다 첫 구절을 대화 원문과 대조한다. 어긋나면 다시 적는다.
- 독자 리포트·치환 목록·반영본·교정본·최종본 같은 중간 파일도 임시 작업 폴더에만 둔다. 작가 폴더에는 저장 요청을 받은 최종 산출물만 쓴다(`저장 경계`).

**기초 수치.** 잠근 원고에 `python3 {BASE}/scripts/check.py --stats 원고.md`를 돌려 1단계 조건 블록에 요약해 넘긴다. 수치 목록은 사실 확인 항목 분류의 출발점이다. 기계 집계는 후보이고 판정은 voice 기준으로 한다. 스크립트는 마크다운 기호가 없는 한 줄짜리 제목·소제목(문장부호로 끝나지 않는 60자 이하 문단)을 문장·종결 통계에서 빼고 그 번호를 따로 알린다. 본문 한 줄이 제목으로 잘못 빠졌으면 그 문단은 데스크가 직접 본다.

**책 기준 탐색.** 책 원고면 아래를 찾아 절대 경로로 기록한다. 없으면 voice 기준만으로 진행하고 멈추지 않는다.

| 순서 | 찾을 곳 | 읽을 파일 |
|---|---|---|
| 1 | 원고 위쪽 폴더의 `00 집필팩/` | `01 집필 정본.md`, `A01_용어사전.md` |
| 2 | 볼트 `04 공용 자료/책 집필팩/01 실용서 공통 기준/` | `A04_문체 가이드.md`, `A03_표기 통일표.md`, `A05_금지어·AI 흔적 사전.md` |

`A01_용어사전`은 원고별 용어집으로 쓴다. 공통 기준 `00 공통 기준 안내.md` 끝 절(일반 글 기준과 충돌하는 항목)은 `책 기준 허용` 판정에 쓴다.

사실 확인 항목은 두 종류로 나눈다.

| 종류 | 예 | 처리 |
|---|---|---|
| 공개 사실 | 발표 날짜, 제품 기능, 기관 이름 | 데스크가 검색으로 확인해 `확인됨(출처)` 또는 `불일치`로 잠근다. 저자에게 묻지 않는다 |
| 저자 경험·자체 수치 | "준비 시간 70% 감소", "지난달 스킬 다섯 개" | 저자만 답할 수 있다. 2단계 `저자 확인`으로 넘긴다 |

같은 대상을 여러 이름으로 부르는 원고(예: MCP·커넥터·MCP 서버)는 1단계 전에 원고별 용어집 후보를 먼저 만들어 독자·편집자에게 함께 넘긴다.

**범위 판정.** 제목·도입(첫 본문 문단)·결론(마지막 문단)이 중심 판단과 본문이 실제로 다루는 범위와 같은지 판정한다. 판정은 셋 중 하나다.

| 판정 | 조건 | 처리 |
|---|---|---|
| 맞음 | 제목이 약속한 것을 본문이 다루고, 본문이 다루는 것을 제목이 덮는다 | 표에 `맞음`만 적는다 |
| 좁음 | 본문이 제목보다 더 넓게 다룬다(예: 제목은 '주제'만, 본문은 독자·강조점·수정 요청까지) | 확인 관문에서 물음 하나: 제목을 본문에 맞출지(4/4에서 후보로), 본문을 제목에 맞출지(2/4에서 본문 수정으로) |
| 넓음 | 제목이 본문보다 큰 것을 약속한다 | 위와 같다 |

제목 없이 접수한 원고(페이스북 게시물 등)는 제목 판정을 `제목 없음`으로 적고 도입·결론만 판정한다. 이때 문단 번호는 첫 문단이 [0]이고, [0]은 도입 문단이다.

작가가 답하지 않으면 `제목을 본문에 맞춤`으로 두고 4/4에서 처리한다. 범위를 본문 쪽에 맞추기로 하면 2/4 진단에 범위 이슈를 High로 올린다. 도입·결론 문단 전체가 지킬 문장이면 판정 대상에서 빼고 `잠금`으로 적는다. 문단 안의 한 문장만 지킬 문장이면 문단은 판정하고, 그 문장만 4/4에서 글자 그대로 둔다.

중심 판단이 진심·풍자·반론 중 어느 것인지 불분명하거나, 수정안이 주장을 반대로 바꿀 수 있으면 1단계 전에 한 번만 묻는다. 확인 전에는 원문의 태도를 바꾼 교체안을 만들지 않는다.

**확인 관문 카드.** 작가는 원고를 이미 갖고 있으므로 전문도, 문단 번호 색인도 내지 않는다. 색인은 이 관문에서 작가가 정할 것(채널·독자·중심 판단·지킬 문장)에 쓰이지 않고, 이후 위치는 제안 관문의 원고 블록 보기가 원문 구절로 보여 준다. 작가가 `문단 번호 보여줘`라고 할 때만 번호와 첫 구절 15자 안팎을 코드 블록 하나로 낸다. 표는 2개까지만 쓴다.

1. **접수 표** — 작가가 확인할 5줄만 낸다: 채널 · 예상 독자 · 중심 판단 · 지킬 문장 · 제목 범위(맞음 / 좁음 — 한 구절 근거 / 넓음 — 한 구절 근거). 지킬 문장은 번호가 아니라 원문 구절로 적는다(예: `"저장 여부보다 무엇을 저장하는가" · "남길 기준을 골라 고치는 파일" · 마지막 문단 전체`). 작가가 지킬 문장을 주지 않았으면 중심 판단을 가장 직접 말하는 원고 문장 하나를 `(중심 판단 문장 — 데스크 지정)`으로 적는다. 이 문장은 2/4·4/4에서 지킬 문장과 같이 다루고, 작가가 빼라고 하면 뺀다. 나머지 접수 카드 항목(기준본·범위·사실 확인·용어집·저장)은 내부에 두고, 작가가 알아야 할 예외(사실 확인 항목이 있음, 승인본을 기준본으로 잡음 등)만 표 아래 한 줄로 적는다.
2. **기초 수치 한 줄** — `분량 1,946자 · 문장 44 · 합니다체 98% · 90자 이상 0 · 금지어 0 · 상투어 0 · 병기 후보 2`처럼 한 줄로 낸다. 걸리는 값이 있을 때만 그 값을 표 아래에 짚는다.

중심 판단이 불명확하면 이 관문의 질문으로 묻는다.

```text
[1/4 원고 확인] 원고를 잠갔습니다 · 다음은 진단·수정 제안
지금 정할 것: 채널·독자·중심 판단·지킬 문장이 맞는지, 제목 범위를 어느 쪽에 맞출지

| 항목 | 값 |
| 채널 | 고스트 블로그 |
| 예상 독자 | … |
| 중심 판단 | … |
| 지킬 문장 | "저장 여부보다 무엇을 저장하는가" · 마지막 문단 전체 |
| 제목 범위 | 좁음 — 제목은 '주제'만, 본문은 독자·수정 요청까지 |

기초 수치: 분량 1,946자 · 문장 44 · 합니다체 98% · 금지어 0 · 상투어 0

다음 단계에서 하는 일
독자 역할은 지금 읽기 시작했습니다. 확인 값이 바뀌면 다시 읽힙니다.
1. 독자 역할이 원고를 읽고 막히는 곳을 적습니다.
2. 편집자 역할이 고칠 곳을 찾고 완성 문장을 만듭니다.
3. 데스크가 원문과 대조해 바뀌는 문단마다 이유와 수정 전·후를 보입니다. 원고는 바꾸지 않습니다.

추천 요청 — 제목 범위가 좁아 제목을 4/4에서 본문에 맞추는 쪽이 본문을 덜 바꿉니다
(코드 블록) 진단해줘, 제목을 본문에 맞춰줘

다른 요청
(코드 블록) 진단해줘, 본문을 제목에 맞춰줘
본문 쪽 범위 수정이 2/4에 꼭 고칠 곳으로 올라옵니다.
```

**진단 선행 실행.** 1단계는 읽기 전용이라 확인 관문에서 작가 답을 기다리는 동안 미리 돌려도 원고가 바뀌지 않는다. 작가가 1/4 카드를 읽는 시간에 독자 역할 대기 시간을 가린다(2026-11-10 실측: 독자 57초 + 편집자 2분 11초 순차).

| 모드 | 선행 실행 |
|---|---|
| 개선형 · 범위 잠금(편집자 단독) · 진단만 | 한다 |
| 심층 개선 | 한다. 독자·편집자를 동시에 백그라운드로 띄운다 |
| 빠른 개선 · 일괄 개선 · 표적 재확인 · 가상 원고 연습 | 하지 않는다 (서브에이전트를 쓰지 않거나 관문 정지가 없다) |

1. 확인 관문 카드를 내는 같은 응답에서, 카드 문장을 쓰기 전에 1단계 ① 독자 호출을 `run_in_background: true`로 띄운다. 조건 블록은 1/4 카드에 적은 값 그대로 넣는다. 범위 잠금은 독자를 생략하므로 편집자를 띄운다.
2. 카드의 `다음 단계에서 하는 일` 첫 줄에 `독자 역할은 지금 읽기 시작했습니다. 확인 값이 바뀌면 다시 읽힙니다.`를 넣는다. 서브에이전트를 부를 수 없어 선행 실행을 못 했으면 이 줄 대신 `독자·편집자 역할을 데스크가 차례로 맡습니다(서브에이전트를 부를 수 없는 환경).`을 넣는다. 빠른 개선은 `데스크가 독자·편집자 역할을 차례로 맡습니다.`를 쓴다.
3. 작가 답보다 독자 완료 알림이 먼저 오면, 그 알림 차례에 편집자를 `run_in_background: true`로 띄우고 작가에게는 한 줄(`독자 검토 끝 · 편집자 진행 중`)만 낸다. 데스크 대조는 작가가 진행을 요청한 뒤에 한다.
4. 작가 답이 오면 확인 값과 대조한다.

| 작가 답 | 처리 |
|---|---|
| 그대로 진행(`진단해줘` 등) | 진행 중이면 기다리고 완료 알림이 오면 데스크 대조로 간다. 새로 부르지 않는다 |
| 예상 독자·중심 판단·지킬 문장·편집 범위(지정 구간)·채널을 바꿈 | 진행 중인 에이전트를 멈추고(TaskStop) 새 조건 블록으로 다시 부른다. 이미 끝난 결과는 버리고 쓰지 않는다 |
| 제목 범위 답: `제목을 본문에 맞춤` | 그대로 진행과 같다. 4/4에서 처리한다 |
| 제목 범위 답: `본문을 제목에 맞춤` | 독자 결과는 재사용한다. 편집자가 아직 안 떴으면 범위 지시(제목이 약속한 범위로 본문을 좁히거나 넓힘, High로)를 조건 블록에 넣어 띄우고, 이미 떴으면 SendMessage로 보낸다 |
| 위 값들과 무관한 지시(분량 상한, 특정 문장 보존 추가) | 독자 결과는 쓰고, 편집자가 아직 안 떴으면 지시를 넣어 띄운다. 이미 떴으면 SendMessage로 추가 지시를 보낸다 |
| `빠르게`·`빠른 개선으로` | 선행 에이전트를 멈추고 빠른 개선으로 간다 |
| `진단만 하고 끝내줘` | 독자 결과는 그대로 쓰고 편집자 결과까지 받아 진단 기록을 낸다 |

5. 완료 알림 전에는 결과를 짐작해 말하지 않는다. 작가가 진행을 물으면 `독자 역할 진행 중`처럼 상태만 답한다.
6. 4/4 확정 `역할 수행` 줄에 `선행 실행(재호출 N회)`를 적고, 버린 결과가 있으면 `실행 지표`에 `재호출 N`을 더한다.

완료 기준: 기준 경로·기준본·범위·중심 판단·보존 영역이 정해졌고, 기초 수치와 (책 원고면) 책 기준 경로가 준비됐다. 선행 실행 대상 모드면 독자(범위 잠금은 편집자)를 백그라운드로 띄웠다. 확인 관문 카드를 내고 멈췄다.
