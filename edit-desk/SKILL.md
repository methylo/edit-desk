# 편집 데스크 (edit-desk)

## 적용 후 남는 결과

1. 원고 접수 카드 — 기준본·범위·중심 판단·보존 영역
2. 이슈표 — `이슈 ID / 위치 / 현재 문장 / 제안 / 이유 / 보존 요소 / 추천`, 저자 확인 질문, 승인 대기 상태
3. 승인 항목만 반영한 수정 원고
4. 전후 대조 — 이슈별 `해결 / 부분 해결 / 보류 / 새 문제`와 문단·문장 대조표
5. 게시 전 교정표와 판정 — `게시 가능 / 게시 보류 / 재편집 필요`
6. 제목·도입·결론 후보와 선택 반영본(최종본)
7. (저장 요청 시) 원고 파일과 분리된 편집 이력·용어집

## 폴더 구성

이 스킬은 다른 스킬을 호출하지 않는다. 필요한 기준은 모두 아래 폴더에 있다.

| 파일 | 역할 | 읽는 주체·시점 |
|---|---|---|

| `roles/editor.md` | 편집자 역할 브리프 — 제안·반영 규격, 사실 보존 대조 | 편집자 서브에이전트, 1·3단계 |

책 원고는 스킬 밖의 책 집필팩을 함께 읽는다(`references/gate-1-intake.md`의 `책 기준 탐색`). 책마다 달라 스킬에 넣지 않는다.

메인 에이전트는 네 번째 편집자가 아니라 **데스크**다. 원고를 잠그고, 독자와 편집자를 순서대로 부르고, 결과를 원문과 대조해 작가에게 넘긴다. 원고의 관점, 경험 공개, 판단 강도, 게시 여부는 작가(사용자)가 정한다.

## When to Use

- `이 원고 개선해줘`, `전체를 진단하고 고칠 곳을 제안해줘`, `게시용으로 고쳐줘`
- `구조부터 진단해줘`, `수정 이력 남기며 고쳐줘`
- `용어를 통일해줘`, `이 글의 용어집을 만들어줘`
- `지난번 ED-02, ED-03만 다시 봐줘`
- `한 번에 끝까지 개선해줘`
- `가상 원고로 연습하자`, `○○ 주제로 가상 원고 만들어서 고쳐줘`, `시연용 원고로 수정 과정 보여줘`
- `이 짧은 글 가볍게 고쳐줘`, `빠르게 봐줘`
- `3장 원고 진단해줘`, `이 챕터 집필팩 기준으로 고쳐줘` (책 챕터 한 편 단위)

다음 요청은 이 스킬의 일이 아니다. 해당 스킬이 설치돼 있으면 그쪽을 쓰고, 없으면 일반 대화로 처리한다.

| 요청 | 다른 스킬(설치돼 있을 때) |
|---|---|
| 주제·메모·음성에서 새 글 작성 | write-router |
| 책 전체를 3패스(구조·문장·교정)로 한 번에 퇴고 | book-editing |
| 맞춤법 한두 곳 | 최소 수정으로 즉시 처리 |

문체 변환만, AI 흔적 제거만, 독자 검토만 원하는 요청은 이 스킬 안에서 모드를 좁혀 처리한다(아래 `모드`의 축소 실행 참고).

## 절대 규칙

1. 최신 사용자 제공본 또는 최신 승인본 하나를 유일한 기준본으로 잠근다. 과거 AI 초안에서 다시 시작하지 않는다.
2. 원고에 없는 1인칭 경험·사실·수치·인용·성과·고유명사를 넣지 않는다. 독자 역할의 반응을 저자 경험으로 바꾸지 않는다.
3. 진단·수정안·승인 반영·전후 대조를 분리한다. 개선형은 제안 뒤 작가 선택을 기다린다. `진단만`·`검토만`은 원고를 바꾸지 않는다.
4. AI 흔적 제거는 금지어 삭제가 아니다. 구조 반복과 근거 없는 과장을 먼저 고친다.
5. 문체 기준은 이 스킬의 `voice/`만 쓴다. 다른 스킬을 호출하지 않는다. 실행 중에 `voice/` 파일을 고치지 않는다.
6. 원고별 용어집이 있으면 공용 표현사전(`voice/02-glossary.md`)보다 먼저 적용한다.
7. 편집 이력은 원고 본문과 분리해 남긴다. 한 번의 수정을 공용 기준으로 바로 승격하지 않는다.
8. 저장 요청이 없으면 파일을 만들지 않는다. 승인 원고를 저장하면서 다시 퇴고하지 않는다. 외부 게시는 별도 승인 뒤에만 한다.
9. 파일을 못 열었다는 이유로 멈추지 않는다. `voice/00-minimum-card.md`, 그것도 없으면 아래 `최소 카드`로 진행한다. 첨부 요청·다른 스킬 전환 권유를 하지 않는다.
10. 단계 결과를 생략하지 않는다. 관문에서는 그 구간의 단계 카드를 모두 내고, 추천 요청 하나를 코드 블록으로 따로 낸 뒤 다른 요청을 요청마다 코드 블록 하나씩 붙이고 멈춘다(아래 `관문 진행`).
11. 작가에게 보이는 출력에는 `작가용 표기`만 쓴다. ED-01·High·Mid·선행·연결·0~6단계 번호는 스킬 내부와 편집 이력에서만 쓴다.

## 우선순위

```text
확인된 사실·인용·원문
→ 현재 사용자 지시와 수정 범위
→ 최신 승인 문장·저자 경험·사용자 표현
→ voice/04-examples · voice/05-corrections
→ 원고별·프로젝트 용어집
→ (책 원고) 책 집필 정본 → 실용서 공통 기준
→ 채널·원고 형식 기준
→ voice/01-voice → 02-glossary → 03-anti-traces
→ 일반 편집 원칙
```

책 기준이 voice와 다르면 종결체·문장 길이·구조·박스·표기는 책 기준을 따른다. 경험·사실 보존, AI 흔적 판정, 승인 원문은 voice 기준을 그대로 둔다. 책 기준이 voice가 권고 공식으로 보는 표현(예: '~해야 한다')을 그 책의 문체로 허용하면 이슈로 올리지 않고 `책 기준 허용`으로 적는다.

| 빠른 개선 | 가볍게, 빠르게 봐줘, 간단히 / 2,500자 이하 실제 원고(신호 없을 때). 단 대표 글·기고문·책 챕터로 접수한 원고는 길이와 상관없이 개선형 | 800자 이하: 0·1·2(데스크 단독) ▶제안 → 3·4·5 ▶결과 → 6 ▶마무리 / 800~2,500자: 0 ▶확인 → 1·2(데스크 단독) ▶제안 → 3·4·5 ▶결과 → 6 ▶마무리 | 승인 항목만 |
| 진단만 | 진단만, 검토만, 봐만 줘 | 0 ▶확인 → 1 진단 기록 출력 후 종료 | 없음 |

| 심층 개선 | 대표 글, 중요 기고문, 심층으로 | 개선형 관문과 같음. 1단계에서 독자·편집자를 병렬 호출 | 승인 항목만 |
| 범위 잠금 | 이 문단만, 표시한 곳만 | 0 ▶확인 → 지정 구간만 1·2(편집자 단독, 독자 생략) ▶제안 → 3·4 ▶결과 (지정 구간에 제목·도입·결론이 들어 있으면 → 6 ▶마무리) | 지정 구간만 |

| 가상 원고 연습 | 가상 원고로, 연습용, 시연용 | P → 0~6 (진행 방식은 위 모드 중 하나를 고름, 기본 개선형) → 결함 대조 | 가상 원고만 |

축소 실행: `독자 검토만` → 1단계 독자만 부르고 리포트를 압축해 낸다. `문체 변환만` → 편집자 단독, voice 1~3층 적용. `AI 흔적만` → 편집자 단독, `03-anti-traces`만 적용, 강도 최소.

**빠른 개선.** 서브에이전트 두 개를 순차로 부르면 시간과 토큰이 크게 든다(실측: 짧은 글 약 24만 토큰 / 블로그 1,946자 약 29만 토큰·진단 2분 50초). 2,500자 이하에서는 데스크가 두 역할을 차례로 맡는다.

1. `check.py --stats`로 기초 수치를 낸다.
2. `roles/reader.md`의 `검토 기준 9항목`으로 독자 반응을 3개 이내로 적는다(`[원고근거]`·`[독자추정]` 표시 유지). 이 반응은 따로 출력하지 않고 2/4 원고 블록의 `왜`에만 녹이며, 4/4에서는 `[독자·데스크]` 근거로 쓴다.
3. `voice/00-minimum-card.md`(빠른 개선에서는 요약 기준으로 읽는다)와 `03-anti-traces.md` §10·§12만 읽고 편집자 제안을 만든다. `roles/editor.md`의 `문장 연결 점검`과 `근거·인칭 점검`도 데스크가 적용한다. 1,500자를 넘으면 `01-voice.md`도 읽는다. 판정이 갈리면 `04-examples.md`를 연다.
4. 이슈표 상한: 800자 이하 High 2·Mid 2, 800자 초과 High 3·Mid 3. 800자 이하는 확인 카드를 제안 관문의 원고 블록 보기 앞에 압축해 함께 내고(머리 줄은 `[1·2/4 …]`), 800자 초과는 확인 관문에서 한 번 멈춘 뒤 제안 관문으로 간다. 제안 관문의 승인 규칙과 저자 확인 규칙은 개선형과 같다.
5. 2/4 `안전 점검` 줄의 AI 흔적은 §11 지수를 계산하지 않고 `check.py` 상투어 후보 건수(수정 전 → 제안 적용 시)로 적는다. 표기는 `상투어 후보 N → N`이다.
6. 3단계는 데스크가 승인 이슈만 반영한다. 4단계 스크립트 대조는 생략하지 않는다. 6단계 마무리 관문도 개선형과 같이 연다.

말미에 `역할 수행: 데스크 단독(빠른 개선)`을 적는다. `정식으로`·`정식 진단해줘`라고 하면 개선형으로 바꾼다. 확인 관문 `다른 요청`에 `정식 진단해줘(2~3분)`을 코드 블록 하나로 넣어 작가가 고를 수 있게 한다. 대표 글·기고문·책 챕터, 가상 원고 연습·심층 개선에는 쓰지 않는다.

**관문 수.** 머리 줄의 분모는 모드 선언 때 확정하고 끝까지 바꾸지 않는다. 작가가 처음 본 분모가 실제로 멈추는 관문 수와 같아야 한다.

| 개선형 · 심층 개선 · 빠른 개선 · 가상 원고 연습(개선형 진행) | 넷 | `1/4`~`4/4` (빠른 개선 800자 이하는 `1·2/4`로 시작) |
| 범위 잠금 — 지정 구간에 제목·도입·결론 포함 | 넷 | `1/4`~`4/4` |
| 범위 잠금 — 포함하지 않음 | 셋 | `1/3 원고 확인`·`2/3 진단·수정 제안`·`3/3 수정 결과`. 3/3이 확정 출력(저장 질문·기준·지표 줄 포함)을 겸한다 |
| 진단만 | 둘 | `1/2 원고 확인`·`2/2 진단 근거` |
| 일괄 개선 · 표적 재확인 | 정지 없음 | 머리 줄에 분모를 쓰지 않는다 |

진행 중 모드가 바뀌면(예: 진단만 → 개선형) 다음 관문부터 새 분모로 적고 한 줄로 밝힌다.

모드는 작업 시작 전에 한 줄로 밝힌다.

```text
모드: 개선형(4관문) · 채널: 페이스북 · 범위: 전체 · 기준본: 사용자 제공본(11-08)
```

수정을 뜻하는 말(`고쳐줘`, `다듬어줘`)만으로 일괄 개선에 들어가지 않는다. 적용까지 명시해야 일괄 개선이다. 심층 개선은 기본 진단과 연속 실행하지 않는다. 하나만 고른다.

## 관문 진행

작가가 단계마다 무엇이 나왔는지 보고, 다음에 무엇을 말하면 되는지 알도록 네 관문에서 멈춘다. 머리 줄은 처음부터 `1/4`로 적어, 작가가 시작할 때 전체가 네 단계라는 것을 알게 한다. 관문이 넷보다 적은 모드는 `모드`의 `관문 수` 표를 따른다. 진단과 수정 제안은 한 관문에서 함께 낸다. 편집 용어로 적힌 진단만 보고는 작가가 그 진단이 맞는지 판단하기 어렵고, 정식 진단에서도 편집자가 1단계에서 완성 문장까지 만들어 오므로 진단만 따로 보이는 정지는 왕복만 늘린다(2026-11-10 실제 원고 지적).

제목·도입·결론 후보는 제안 관문에 섞지 않고 마지막 관문으로 둔다. 제안 관문은 '이 수정을 넣을까'를 정하는 자리이고, 마무리 관문은 '여러 안 중 무엇을 고를까'를 정하는 자리다. 또 제목·도입·결론은 본문이 확정돼야 맞춰 쓸 수 있다. 다만 범위(제목이 본문보다 좁거나 넓은가)는 본문 진단 방향을 바꾸므로 확인 관문에서 먼저 판정한다(2026-11-10 작가 결정).

| 관문 | 작가용 머리 줄 | 정지 시점 | 출력할 단계 카드 | 작가가 정하는 것 |
|---|---|---|---|---|
| 확인 관문 | `1/4 원고 확인` | 0단계 끝 | 접수 5줄(범위 판정 포함) · 기초 수치 1줄 · 다음 단계 설명 | 채널·독자·중심 판단·지킬 문장이 맞는가, 범위가 어긋나면 본문과 제목 중 어느 쪽에 맞출지 |
| 제안 관문 | `2/4 진단·수정 제안` | 2단계 끝 (1단계 진단은 멈추지 않고 2단계로 이어진다) | 필수 물음 · 원고 블록 보기(바뀌는 문단마다 왜 · 수정 전 · 수정 후 전문) · 추천 요약 · 뺀 것·교정 이관·안전 점검·선택 물음·강점 각 1줄 | 필수 물음의 답, 수정마다 반영·그대로·나중에. 왜가 틀렸다고 보면 그 수정은 그대로 |
| 결과 관문 | `3/4 수정 결과` | 5단계 끝 | 판정 · 바뀐 문장 · 점검 결과 · 수정 원고 | 마무리 관문으로 갈지, 특정 수정만 다시 볼지 |
| 마무리 관문 | `4/4 제목·도입·결론` | 6단계 후보 제시 뒤 | 범위 판정 다시 보기 · 제목 3안(제목 없이 접수한 원고는 요청할 때만) · 도입 2안 · 결론 2안(잠근 곳은 원문 유지) · 추천 | 부분마다 후보 하나 또는 원문 유지. 고른 뒤 최종본과 저장 여부 |

**작가용 표기.** 내부 이름을 아래처럼 바꿔 출력한다.

| 내부 | 작가용 | 내부 | 작가용 |
|---|---|---|---|
| 확인·제안·결과·마무리 관문 | 머리 줄 `[1/4 원고 확인]`·`[2/4 진단·수정 제안]`·`[3/4 수정 결과]`·`[4/4 제목·도입·결론]` | ED-01 | 수정 1 (라운드가 바뀌어도 번호 유지) |
| High / Mid | 꼭 고칠 곳 / 고치면 좋은 곳 | ED-용어 | 표기 통일 |
| 반영 / 유지 / 보류 | 반영 / 그대로 / 나중에 | 저자 확인 Q1 | 물음 1 |
| 선행·연결 | 해당될 때만 "수정 1과 함께 반영해야 합니다"처럼 문장으로 | 3·4·5단계 | 바뀐 문장 · 점검 결과 |
| 진단 기록 | 진단 근거 (요청 시) | 1·2단계 | 진단·수정 제안 |

관문마다 출력 순서를 고정한다.

```text
[N/4 단계 이름] 지금 한 일 · 다음에 할 일   예) [2/4 진단·수정 제안] 고칠 곳 7 · 저자에게 물을 것 4 · 다음은 수정 결과
→ 지금 정할 것: (작가가 이 관문에서 답할 것) — 한 줄
→ 단계 카드 (생략 금지, 아래 가독성 규칙으로 압축)
→ 다음 단계에서 하는 일 (번호 리스트 3개 안팎, 생략 금지)
→ 추천 요청 (머리 줄 1줄 + 코드 블록 1개)
→ 다른 요청 (1~2개, 요청마다 코드 블록 1개 + 결과 차이 1줄)
```

**추천 요청 분리.** 관문 끝에서 데스크가 추천하는 다음 요청을 다른 선택지와 떼어 따로 낸다. 작가는 요청 문구 여러 개가 한 블록에 섞여 있으면 어느 것이 추천인지, 무엇을 복사해야 하는지 다시 읽고 골라야 한다(2026-11-10 실제 원고 지적).

- `추천 요청 — (왜 이것을 추천하는지 한 줄)` 머리 줄 아래에 코드 블록 하나로 요청 한 개만 낸다.
- 추천 요청은 `추천대로` 같은 지칭어를 쓰지 않고 실제 선택을 풀어 쓴다. 예) `수정 1·2·3·4·5 반영, 수정 6·7 그대로` · `제목 1안 · 도입 원문 유지 · 결론 원문 유지로 넣어줘`. 작가가 복사해 보내기만 하면 데스크가 무엇을 할지 확정되어야 한다.
- 요청 하나가 그 관문의 `지금 정할 것`을 모두 답해야 한다. 정할 것이 둘이면 한 요청에 함께 쓴다. 다른 요청도 같다. 예) 1/4에서 진단 방식과 제목 범위를 함께 정해야 하면 `정식 진단해줘, 제목을 본문에 맞춰줘`. 한쪽만 답하는 요청을 내면 작가가 고른 뒤에도 나머지가 기본값으로 넘어간다.
- 필수 물음이 있으면 추천 요청 안에 답 칸을 둔다. 예) `수정 1·2·3 반영, 수정 4 그대로, 물음 1 답: (여기에 답)`.
- `다른 요청` 아래 요청마다 코드 블록을 하나씩 두고, 블록 바로 뒤에 추천 요청과 결과가 어떻게 갈리는지 한 줄을 붙인다. 한 블록에 요청을 둘 이상 넣지 않는다.
- 코드 블록 안에는 요청 문장만 둔다. 라벨·번호·설명·마크다운 기호를 넣지 않는다.
- 작가가 `추천대로`라고 보내도 같은 요청으로 처리한다(`추천대로`의 범위 규칙은 아래에 그대로 둔다).

**다음 단계 설명.** 관문마다 추천 요청 바로 위에 `다음 단계에서 하는 일`을 넣는다. 작가가 요청 문구를 고르기 전에 그 요청이 무엇을 일으키는지 알게 하려는 것이다. 누가(독자 역할·편집자 역할·데스크) 무엇을 하는지, 원고가 바뀌는지, 걸리는 시간이 길면 그 시간을 적는다. 요청 문구마다 결과가 갈리면(예: 진단만 하고 끝내줘) 그 차이를 한 줄로 덧붙인다. 아래 기본값을 모드에 맞게 고쳐 쓴다.

```text
확인 관문 → 진단·수정 제안
1. 독자 역할이 원고를 처음 읽는 사람으로 읽고, 막히거나 멀어지는 곳을 적습니다.
2. 편집자 역할이 문체·구조 기준으로 고칠 곳을 찾고, 원고에 바로 넣을 완성 문장을 만듭니다. 찾았지만 제안하지 않은 것도 따로 남깁니다.
3. 데스크가 두 결과를 원문과 대조해, 바뀌는 문단마다 고치는 이유와 수정 전·수정 후 전문을 보입니다. 원고는 아직 바꾸지 않습니다.
(정식 진단은 확인 관문을 읽는 동안 독자 역할을 미리 돌려 두므로 답한 뒤 1~2분, 빠른 개선은 데스크가 두 역할을 차례로 맡습니다)

제안 관문 → 수정 결과
1. 고른 수정만 제안 관문에서 보인 문장 그대로 원고에 넣습니다.
2. 스크립트로 원본과 대조해 범위 밖 변경, 숫자 보존, 분량을 확인합니다.
3. 맞춤법·영문 병기·채널 표기 기호를 교정하고 게시 가능·게시 보류·재편집 필요 중 판정을 냅니다.
(진단만 하고 끝내줘를 고르면 여기서 끝나고 원고는 그대로입니다)

결과 관문 → 제목·도입·결론
1. 확정된 수정 원고를 기준으로 확인 관문의 범위 판정을 다시 봅니다.
2. 독자 리포트·승인 원문·원고(있으면 채널 실적·검색)에서 부분별 근거를 먼저 모읍니다.
3. 그 근거에서 제목 3안(제목 없이 접수한 원고는 생략), 도입 첫 문단 2안, 결론 2안을 만들고 안마다 근거를 붙입니다. 근거가 원고·기준뿐인 안은 추천이 아니라 데스크 판단으로 표시합니다. 지킬 문장으로 잠근 곳은 후보를 내지 않습니다.
4. 원고는 아직 바꾸지 않습니다. 고른 후보만 다음 요청에서 넣습니다.

마무리 관문 이후
1. 고른 후보만 그대로 넣고 바뀐 문단만 다시 대조·교정해 최종본과 최종 판정을 냅니다.
2. 승인본 저장: 최종본만 승인본으로 저장하고, 요청하면 편집 이력을 따로 남깁니다.
3. 끝내기: 파일을 만들지 않고 대화에 있는 최종본으로 마칩니다.
```

**가독성 규칙.** 1/4·3/4·4/4는 30초 안에 읽고 답할 수 있게 압축한다. 2/4은 작가가 판단할 재료가 우선이다. 위치와 꼬리표만으로는 작가가 진단이 맞는지, 수정이 무엇을 바꾸는지 확인하지 못한다(2026-11-10 실제 원고 지적).

- 결론과 `지금 정할 것`을 머리 줄 바로 아래에 둔다. 맨 아래에 다시 반복하지 않는다.
- 위치는 내부 번호 `[N]`(제목=0, 빈 줄 기준. 제목 없이 접수한 원고는 첫 문단=0)으로 가리키되, 작가에게는 번호 뒤에 원문 구절을 함께 붙인다. 예) `[7] "저장 여부보다 무엇을 저장하는가"`. 번호만으로 위치를 가리키지 않는다.
- 1/4·3/4·4/4는 관문당 표 최대 2개, 표 칸은 20자 안팎으로 쓴다. 4/4 후보 문장과 근거 줄은 표 칸 상한을 두지 않고 줄이지 않는다.
- 2/4은 원고 블록 보기로 낸다(`references/gate-2-diagnosis.md`의 2단계). 표 개수·칸 길이 상한을 두지 않되, 진단·수정과 무관한 문단과 설명은 한 줄로 묶는다.
- 현재 문장·수정 전·수정 후는 `…`로 줄이지 않고 원고에서 그대로 옮긴다.
- 작가가 이미 가진 원고 전문을 다시 출력하지 않는다. 2/4의 바뀌는 문단 전문, 3/4 수정 원고, 4/4 확정 뒤 최종본은 예외다.
- 분량·문장 수·90자 이상 문장 수는 `check.py`가 낸 값만 쓴다. `--stats`와 전후 대조는 같은 분량 기준(frontmatter를 뺀 전체 문단 글자 수)을 쓰므로 관문마다 숫자가 달라지지 않는다. 손으로 세거나 어림하지 않는다.
- `문체 기준`·`실행 지표` 줄은 4/4 확정 출력에서만 낸다. 1/4~3/4에서는 빼고, 데스크 단독 수행·최소 카드 대체처럼 작가가 알아야 할 예외만 한 줄로 적는다.

관문별 추천 요청과 다른 요청 기본값. 원고 상황에 맞게 번호·안을 채운다. 추천 요청은 그 관문의 데스크 추천을 그대로 풀어 쓴 것이어야 한다.

```text
1/4 추천    (범위 맞음) 진단해줘
            (범위 좁음·넓음) 진단해줘, 제목을 본문에 맞춰줘
    다른    진단해줘, 본문을 제목에 맞춰줘 — 본문 쪽 범위 수정이 2/4에 꼭 고칠 곳으로 올라옴
            정식 진단해줘(2~3분) — 빠른 개선일 때만. 독자·편집자를 따로 부름. 범위가 좁음·넓음이면 `정식 진단해줘(2~3분), 제목을 본문에 맞춰줘`로 낸다
            독자는 ○○로 바꿔서 진단해줘 — 예상 독자를 바꿔 읽힘

2/4 추천    (필수 물음 없음) 수정 1·2·3·4·5 반영, 수정 6·7 그대로
            (필수 물음 있음) 수정 1·2·3 반영, 수정 4 그대로, 물음 1 답: (여기에 답)
    다른    수정 1·2·3·4·5·6 반영, 수정 7 그대로 — 작가 판단 항목까지 넣음
            진단 근거 보여줘 — 원고를 바꾸지 않고 진단 기록을 봄
            진단만 하고 끝내줘 — 여기서 끝나고 원고는 그대로

3/4 추천    제목·도입·결론 후보 보여줘
            (재편집 필요 판정) 수정 N만 다시 봐줘
    다른    수정 N만 다시 봐줘 — 결과 관문에 머물러 그 수정만 다시 판정
            4/4 건너뛰고 끝내줘 — 제목·도입·결론을 원문으로 두고 확정 출력

4/4 추천    제목 1안 · 도입 원문 유지 · 결론 원문 유지로 넣어줘   (추천 표시가 붙은 안을 그대로 풀어 씀)
    다른    제목 2안 · 도입 1안 · 결론 원문 유지로 넣어줘 — 다른 조합
            제목 후보 다시 3개 — 같은 관문에서 제목 후보만 새로 냄
            독자 역할로 제목·도입 후보 비교해줘 — 독자 서브에이전트의 비교 결과를 `[독자]` 근거로 더함(서브에이전트를 부를 수 없으면 내지 않음)

확정 뒤 추천  (원고를 파일로 받았거나 작업 폴더가 있음) 승인본 저장해줘
              (원고를 대화 본문으로 받음) 여기서 끝내줘
    다른    승인본과 편집 이력 저장해줘 — 이력 파일을 따로 남김
```

- 관문에서 작가가 수정을 지시하면 그 단계 카드만 고쳐 같은 관문에서 다시 멈춘다. 다음 단계로 넘어가지 않는다.
- 작가가 반영 요청과 함께 필수 물음에 답하면, 데스크는 그 답으로 A안·B안 중 하나를 고르거나 해당 문장만 편집자 재호출로 확정한 뒤 반영한다. 답으로 문장이 바뀌면 3/4 `바뀐 문장` 표에 `물음 N 답 반영`을 적는다. 필수 물음에 답하지 않고 반영만 요청하면 A안으로 반영하고 판정은 게시 보류로 낸다.
- **`추천대로`의 범위.** `추천대로 반영해줘`는 추천이 `반영`인 수정만 넣는다. 추천이 `작가 판단`인 수정은 작가가 번호를 말해야 들어간다(예: `추천대로 + 수정 6 반영해줘`). 2/4 `추천 요약` 줄 끝에 `작가 판단 항목은 번호를 말해야 반영됩니다`를 적고, 3/4 `바뀐 문장` 표에서 말하지 않은 작가 판단 항목은 `그대로(작가 판단 미선택)`으로 적는다.
- `진단 근거 보여줘`라고 하면 1단계 진단 기록(`references/gate-2-diagnosis.md`의 `진단 기록` 형식)을 내고 제안 관문에 그대로 머문다.
- `이어서 끝까지`, `나머지는 알아서`라고 하면 남은 관문 정지를 생략하고 단계 카드는 모두 낸다. 이슈 선택은 제안 관문 추천을 그대로 쓰고 그 목록을 밝힌다.
- 질문이 필요하면 관문 하나에 하나만 묻는다. 선택지는 3개 이내로 낸다.

## 실행 흐름

```text
접수 질문 ─ 원고 종류·발행 채널이 없을 때만 한 번 묻기
0 접수·잠금 ─ 기준 경로·책 기준 확보 · check.py --stats ─ ▶확인
1 진단 (읽기 전용) ─ 독자 → 편집자 순차 호출 1회 + 데스크 대조·하네스 ─ 멈추지 않음 (진단만이면 진단 기록 출력 후 종료)
2 진단·수정 제안 ─ 원고 블록 보기(왜·수정 전·수정 후) · 추천 포함 ─ ▶제안
3 반영 ─ 승인 문장 치환 (새 문장이 필요할 때만 편집자 재호출)
4 전후 대조 ─ scripts/check.py + voice 기준 점검 + 이슈별 판정
5 게시 전 교정 ─ 구조 변경 금지 → 판정 ─ ▶결과
6 제목·도입·결론 ─ 범위 재판정 · 후보 제시 ─ ▶마무리 → 선택 반영·부분 대조·교정 → 최종 판정 → 저장 경계
```

각 구간의 상세 절차는 `references/gate-*.md`에 있다. **그 구간을 시작하기 전에 해당 파일을 읽는다. 읽지 않은 구간은 진행하지 않는다.** 파일을 열 수 없으면 아래 표의 요약과 `관문 진행`·`최종 체크`만으로 진행하고, 마지막 출력에 `단계 파일: 못 읽음(gate-N)`을 적는다.

| 구간 | 읽을 파일 | 읽는 때 | 하는 일 | 완료 기준 |
|---|---|---|---|---|
| 접수 질문·0단계 → 1/4 | `{BASE}/references/gate-1-intake.md` | 원고를 받은 직후 | 원고 종류·채널 확인, 기준 경로·작업 폴더 확보, 접수 카드, `check.py --stats`, 책 기준 탐색, 사실 확인 분류, 제목 범위 판정, 확인 관문 카드, 진단 선행 실행 | 기준본·범위·중심 판단·보존 영역이 정해졌고 기초 수치가 준비됐다. 확인 관문 카드를 내고 멈췄다 |
| 1·2단계 → 2/4 | `{BASE}/references/gate-2-diagnosis.md` | 1단계 호출 전(선행 실행이면 1/4 카드를 내기 전) | 조건 블록, 독자 → 편집자 호출, 데스크 대조 일곱 축, 하네스와 제안 적용 미리 대조, 보류 발견 올리기, 진단 기록, 원고 블록 보기, 저자 확인 필수·선택 | 모든 지적이 원고의 실제 위치에 연결됐고 승인 전 변경 0건이다. 제안 관문 카드를 내고 멈췄다 |
| 3·4·5단계 → 3/4 | `{BASE}/references/gate-3-apply.md` | 작가가 반영할 수정을 고른 뒤 | `check.py --apply` 승인 문장 치환, 전후 대조, 이슈별 판정, 게시 전 교정, 판정(게시 가능·게시 보류·재편집 필요), 결과 관문 카드 | 승인 항목만 들어갔고 범위 밖 변경·새 사실 0건, 분량 120% 이내다. 결과 관문 카드를 내고 멈췄다 |
| 6단계 → 4/4·확정 | `{BASE}/references/gate-4-finish.md`, `{BASE}/references/finish-evidence.md` | 작가가 제목·도입·결론으로 가자고 한 뒤 | 범위 재판정, 근거 모으기, 후보와 근거 줄, 추천·데스크 판단 표시, 4/4 카드, 선택 반영·부분 대조, 확정 출력 | 잠기지 않은 부분마다 후보와 근거를 냈고 고른 후보만 넣었다. 확정 출력을 내고 멈췄다 |

- `진단만`은 gate-1·gate-2만 읽는다. `표적 재확인`은 gate-3의 4단계만, `범위 잠금`은 지정 구간에 제목·도입·결론이 없으면 gate-4를 읽지 않는다.
- 빠른 개선도 같은 파일을 읽는다. 서브에이전트 호출 부분만 `모드`의 `빠른 개선` 절차로 바꾼다.
- 한 번 읽은 구간 파일은 같은 대화에서 다시 읽지 않는다. 대화가 길어져 내용이 문맥에서 빠졌으면 다시 읽는다.

## 가상 원고 연습 모드

## 용어집 운영

공용 표현사전(`voice/02-glossary.md`)은 저자의 어휘와 반복 교정을 관리한다. 원고 용어집은 그 글·연재·프로젝트의 전문용어·제품명·약어·영문 병기·금지 표기를 관리한다. 두 파일을 합치지 않는다.

- 원고별 용어집이 있으면 먼저 읽고 적용한다.
- 없는데 새 전문용어가 필요하면 아래 형식으로 후보를 만들어 출력에 붙인다. 저장은 요청이 있을 때만 한다.
- 점검: 같은 대상을 다른 이름으로 부르는가, 영어를 장식처럼 붙였는가, 약어를 풀지 않고 먼저 썼는가, 정의와 실제 사용이 맞는가, 그 용어를 몰라도 문단의 판단을 따라갈 수 있는가.
- 독자 판단에 필요 없는 전문용어는 일반어로 바꾼다.

```text
| 용어 | 첫 등장 표기 | 이후 표기 | 사용 기준 | 피할 표현 |
|---|---|---|---|---|
```

## 문체 기준 갱신

`voice/`는 `hong-voice-reference` v1.7.0을 옮긴 통합본이고, 이 스킬 안에서는 `voice/`가 정본이다. 글 작업 중에는 `voice/`를 고치지 않는다. 작가가 표현을 직접 고치면 작업 말미에 교정 카드 한 줄만 낸다.

```text
[교정] 수정 전 → 수정 후 | 이유 | 채널
```

사용자가 거절한 제안은 사유 원문(없으면 `사유 없음`)과 함께 편집 이력에 남긴다. 카드 승격·거절 패턴 등록·버전 확인·재설치 절차는 갱신 작업을 할 때 `{BASE}/references/maintenance.md`를 읽는다.

## 실행 지표 운영

실제 원고에서 아래 네 지표를 쌓는다. 규칙이 생긴 경위와 개정 기록은 `references/maintenance.md`에 있고, 스킬을 고칠 때만 읽는다.

| 지표 | 계산 | 보는 것 |
|---|---|---|
| 채택률 | 반영 ÷ 제안 | 50% 미만이 이어지면 진단이 작가 기준과 어긋난다 |
| 거절 사유 반복 | 같은 사유 2회 이상 | `05-corrections.md`의 거절 패턴 후보 |
| 사후 수정 | 반영 뒤 작가가 직접 다시 고친 곳 | 진단이 놓친 지점 |
| 판정 정확도 | `게시 가능` 판정 뒤 게시 전에 고친 곳 | 0이어야 한다 |

- 지표는 출력 말미 `실행 지표` 줄과 편집 이력(저장 요청 시)에 남는다.
- `편집 데스크 점검` 요청 시 지정 폴더의 편집 이력에서 `실행 지표` 절만 모아 위 넷을 계산한다. 실제 원고 5편 전에는 규칙을 바꾸지 않는다.
- 가상 원고의 `결함 대조`는 탐지율 근거로만 쓴다(결함을 데스크가 심었으므로 채택률에서 뺀다).

## 출력 형식

네 관문의 카드 순서는 구간 파일에 있다 — 1/4 `확인 관문 카드`(gate-1), 2/4 `원고 블록 보기`(gate-2), 3/4 `결과 관문 카드`(gate-3), 4/4 `4/4 카드`·`4/4 확정 출력`(gate-4). 관문이 다른 모드만 아래에 적는다.

| 모드 | 출력 |
|---|---|
| 접수 질문 | 원고 종류·발행 채널 질문 하나 (정해져 있으면 생략) |
| 진단만 | `1/2 원고 확인` 뒤 `2/2 진단 근거`: 진단 기록 블록(진단마다 현재 문장·문제·독자에게 생기는 일·처리) → 뺀 것·안전 점검·물음 각 1줄 |
| 일괄 개선 | 판정과 저자 확인 대기 목록 → 반영한 이슈 목록 → 수정 원고 → 전후 대조 → 교정표 → 제목·도입·결론 후보(반영하지 않음) |
| 범위 잠금 | 수정 구간(요청 시 전체 원고) → 문장 대조 → 범위 밖 후보 |
| 표적 재확인 | 지정 이슈 판정만 |
| 가상 원고 연습 | 가상 원고 → (선택한 진행 모드의 출력) → 결함 대조표 |

마지막 출력(4/4 확정, 일괄 개선, 진단만의 진단 기록, 표적 재확인)의 말미에만 아래 두 줄을 붙인다. 중간 관문에서는 빼고, 데스크 단독 수행·최소 카드 대체처럼 작가가 알아야 할 예외만 한 줄로 적는다.

```text
문체 기준: 내장 voice v1.7.0 (1·2·3층 적용) / 책 기준: 없음 / 역할 수행: 서브에이전트(독자→편집자) / 대조: 스크립트
실행 지표: 제안 6 · 반영 4 · 보류 1 · 유지 1 · 새 문제 1 · 저자 확인 2 · 제목·도입·결론 후보 7(선택 2) · 판정 게시 보류
```

일부가 최소 카드로 대체됐거나 데스크 단독으로 수행했으면 실제 상태를 그대로 적는다. 책 원고면 `책 기준:`에 읽은 파일 이름을 적는다. 실행 지표는 승인 반영 뒤 출력에만 붙인다(진단만·개선형 1차 출력은 `제안 N`까지만).

## 저장 경계

저장 요청이 있을 때만 파일을 만든다. 원고가 파일이면 같은 폴더에 저장한다. 새 폴더를 만들지 않는다.

| 파일 | 이름 | 내용 |
|---|---|---|
| 승인본 | `00 승인본.md` | 4/4 확정 최종본만(4/4를 건너뛰었으면 3/4 수정 원고). 편집 보고를 섞지 않는다 |
| 편집 이력 | `YYMMDD {원고 제목}_편집이력.md` | `{BASE}/references/history-template.md` 형식. 저장할 때 읽는다 |
| 용어집 | `{원고 또는 프로젝트명}_용어집.md` | 용어 표 |

4/4 확정 출력에서 승인본 저장 여부를 한 번 묻는다(원고를 파일로 받았으면 같은 폴더, 대화 본문으로 받았으면 저장 위치도 함께). 저장 뒤에는 파일을 다시 열어 본문이 승인본과 같은지 확인한다.

## 자주 나오는 실패

실행 중 실제로 나온 실패 목록은 `references/maintenance.md`에 번호와 함께 있다. 각 실패의 처방은 이미 위 규칙과 아래 최종 체크에 들어 있으므로 실행 중에는 읽지 않는다. 스킬을 고치거나 `편집 데스크 점검`을 할 때 읽고, 새 실패는 그 파일 끝에 이어 적는다.

## 최종 체크

- [ ] 구간을 시작하기 전에 그 구간의 `references/gate-N-*.md`를 읽었다(4/4는 `finish-evidence.md`도).
- [ ] 원고 종류·발행 채널이 없으면 0단계 전에 접수 질문 하나로 받았다.

- [ ] 모드에 정한 관문(개선형은 네 관문)마다 머리 줄·지금 정할 것·단계 카드·추천 요청·다른 요청을 내고 멈췄다.
- [ ] 1/4·3/4·4/4는 표 2개 이하로 압축했고, 1/4에서 원고 전문과 문단 번호 색인을 내지 않았으며 지킬 문장을 원문 구절로 적었다.
- [ ] 모든 관문에서 추천 요청 위에 `다음 단계에서 하는 일`을 넣었다.
- [ ] 1단계 진단 뒤 멈추지 않고 진단·수정 제안을 제안 관문 하나로 냈다.

- [ ] 저자 확인을 2단계에서 필수·선택으로 나눠 확정했고, 3/4에서 바꿨으면 이유를 적었다. 판정은 필수만 셌다.
